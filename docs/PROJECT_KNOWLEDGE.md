# Mov!n 프로젝트 지식 기준

이 문서는 이전 `hack` 프로젝트에서 학습한 기획·청사진·탄소 산정 내용을 현재 저장소의 개발 기준으로 옮긴 것이다. 구현 판단이 충돌하면 아래의 출처 우선순위를 따른다.

## 출처 우선순위

1. `docs/reference/hack/final-plan.pdf` — 제품 범위와 최종 의사결정의 최우선 기준
2. `docs/reference/hack/carbon-emissions-methodology.docx` — 탄소 산정식·계수·검증 결과의 기준
3. `docs/reference/hack/blueprint-1.png` ~ `blueprint-4.png` — 서비스 흐름과 UI 의도의 시각 자료
4. `docs/HACK_CONVERSATIONS.md` — 작업 이력, 결정 배경, 이식 상태 기록

청사진과 최종 기획안이 충돌하면 최종 기획안을 따른다. 대표적인 충돌은 `blueprint-2.png`의 선택형 자동 수락이다. 최종 기획안은 자동 수락을 명시적으로 폐기했으므로 제품에 자동 수락 기능을 넣지 않는다.

## 한 문장 정의

화주·주선사가 화물을 발주하는 순간, 조건을 조금 바꾸면 수락 가능 차주 수·예상 운임·배차 시간이 어떻게 달라지는지 즉시 보여주는 AI 배차 코파일럿이다.

기존 서비스가 정해진 조건에 맞는 매물을 찾게 한다면, Mov!n은 조건을 확정하기 전에 조건별 결과 차이를 먼저 보여준다. 사용자를 대신해 결정하지 않고 더 나은 선택지와 판단 근거를 제공한다.

## 제품 발전 구조

### Stage 1 — 개입과 수집

- 콜 등록 중 조건 완화에 따른 결과 차이를 즉시 제시한다.
- 수락·거절·무시 반응과 협상/인상 이력을 학습 데이터로 축적한다.
- 마감까지 남은 시간과 최종 운임의 관계인 `마감 임박 곡선`을 핵심 예측 엔진으로 삼는다.
- 기준 데이터만으로 첫날부터 개입할 수 있고, 반응이 쌓일수록 정확해지는 구조다.

### Stage 2 — 진단과 승격

- 누적 데이터로 물류비 벤치마크와 원인 분해를 제공한다.
- 순서는 `단건 개입 → 누적 진단 → 개선 → 등급`이다. 등급이 진단의 입장 조건이 되어서는 안 된다.
- 파트너스 혜택은 할인보다 캐파 보증, 성과 증명 리포트, 사고 시 우선 대응에 둔다.
- 핵심 메시지는 “싸게 쓰는 것이 아니라 확실하게 쓴다”이다.

### Stage 3 — 예측과 복화 체인

- 파트너스의 발주 패턴이 충분히 모인 뒤 물량을 예측하고 운송인의 귀로 화물을 설계한다.
- 역방향 수요가 확보되기 전에는 복화 체인을 제품의 확정 성과처럼 주장하지 않는다.

## 시스템 구조

- 백엔드와 AI 엔진은 하나다.
- 화주·주선사용 프론트와 운송인용 프론트는 분리한다.
- 현재 화면 경로는 `/shipper`, `/carrier`이며 `/`는 화주 화면을 표시한다.
- 백엔드가 복잡해도 사용자에게 보여주는 정보는 간소화한다.

## 화주·주선사 흐름

1. 노선, 중량, 차종, 상차 시각과 시간창을 입력한다.
2. 입력하는 순간 AI가 현재 조건과 완화 조건을 비교한다.
3. 사용자는 현재 조건을 유지하거나 완화 조건을 선택한다. 두 선택은 UI에서 대등하게 보여야 한다.
4. 수락·거절·무시와 실제 체결 결과를 기록한다.
5. 누적 데이터로 벤치마크와 개선 처방을 만든다.
6. 조건을 바꾸지 않아도 불이익을 주지 않는다.

대표 데모 비교:

- 현재 조건: 수락 가능 차주 100명, 예상 운임 42만원, 예상 배차 40분
- 하루 완화: 수락 가능 차주 3,400명, 예상 운임 38만원, 예상 배차 15분
- 화면에는 `34배`, `4만원 절감`, `25분 단축`처럼 델타를 명확히 표시한다.
- 점 추정만 보여주지 않고 범위와 신뢰도를 함께 표시한다. 예: `36~41만원, 신뢰도 78%`.
- 최근 90일 실거래, 수요 피크, 안전운임 준수 범위 등 산출 근거를 노출한다.

## 운송인 흐름

### 사전

- 노선, 화물 종류, 시간대, 귀가 희망을 등록한다.
- 주 대기 위치와 시간 패턴을 축적한다.
- 선착순 경쟁이 아닌 적합도 기반 매칭을 지향한다.

### 운행 중

- 도착 예정 시각과 평균 대기시간을 짧게 브리핑한다.
- 다음 콜 후보 3건을 수입, 유류비, 공차거리, 소요시간, 다음 복화 가능성, 귀가 가능 여부로 비교한다.
- 정렬 기준은 표면 운임이 아니라 예상 실수령이다.

대표 데모 사례:

- 부산→서울: 운임 47만원, 유류 7.4만원, 공차 1.4만원, 실수령 38.2만원, 내일 귀가 가능
- 대구→인천: 운임 52만원, 유류 9.1만원, 공차 8.3만원, 실수령 34.6만원, 공차 88km·11시간·귀가 어려움
- 부산→포항: 운임 24만원, 유류 3.2만원, 공차 1.0만원, 실수령 19.8만원, 짧고 일찍 끝남

가장 높은 운임이 최선의 콜이 아닐 수 있음을 비용 분해로 설명해야 한다.

### 판단과 사후

- 최종 선택은 항상 운송인이 직접 한다.
- 자동 수락 기능은 넣지 않는다.
- 선택하지 않은 이유를 짧게 받아 선호 데이터로 되돌린다.
- 월간 리포트는 성과를 먼저 보여주고 개선 제안은 그다음에 둔다.

## 핵심 UX 원칙

- 조건 변경을 강요하지 않는다.
- 안 바꿔도 불이익이 없다.
- 두 선택 버튼을 대등하게 배치한다.
- 적합도와 예측 산정 근거를 공개한다.
- 예측은 범위·확률·신뢰도와 함께 표시한다.
- 데이터가 부족하면 억지로 예측하지 않고 `데이터 축적 중`이라고 표시한다.
- 신규·저평가 차주가 구조적으로 배제되지 않게 한다.
- 최종 선택 권한은 화주와 운송인에게 남긴다.
- 상대방의 지불의사나 내부 정보를 넘기지 않고 각자에게 자기 위치만 알려준다.
- 예상보다 비싸진 경우에는 원인을 사후 설명한다.

## 의도적으로 제외한 범위

- `협상`을 전면에 둔 제품 프레임
- 복화를 화주 설득의 초기 핵심 근거로 사용하는 것
- 방어하기 어려운 `최적해` 또는 완전 최적화 주장
- 양측 조건을 동시에 조정하는 구조
- AI 자율 협상 에이전트
- 주선사 대체
- 완전한 정보 대칭
- 자동 수락

제품 표현은 `최적화`보다 `개선`, `정답`보다 `선택지와 판단 기준`에 둔다.

## 데이터 명세

### 콜 등록 이력

- 콜 ID, 등록 주체 ID, 등록 일시
- 출발지, 도착지, 중량, 차종, 품목
- 상차 희망 시각과 시간창 폭
- 하차 희망 시각과 시간창 폭
- 제시 운임, 최종 체결 운임
- 결과(성사/유찰), 배차 소요 시간
- 인상 이력

핵심 파생값:

- 리드타임 = 상차 희망 시각 - 등록 일시
- 시간창 폭 = 조건 경직도
- 제시가 대비 체결가 배율
- 마감까지 남은 시간 대 최종 운임 = 마감 임박 곡선

### 개입 반응 로그

- 콜 ID, 제시한 대안, 예측값
- 사용자 반응: 수락·거절·무시
- 선택형 거절 사유
- 실제 체결 운임과 배차 소요 시간

### 운송인 데이터

- 차량 제원: 톤급, 차종, 특수장비
- 수락·거절 이력과 거절 사유
- 실제 운행 이력: 노선, 시간대, 빈도
- 실제 수락 운임 분포
- 명시 선호와 대기 위치 패턴
- 이행률과 노쇼 이력

명시 설정은 오래되어 부정확할 수 있으므로 실제 행동 로그를 더 강한 신호로 취급한다.

### 외부 참조 데이터

- 안전운임 고시
- 노선별 거리와 소요시간
- 유가
- 노선·시간대별 수급

## 가상 데이터 생성 기준

- 주체별 습관을 심는다.
- 시간창이 좁을수록 유찰률, 인상 횟수, 최종 운임이 높아지는 상관관계를 심는다.
- 약 20%는 예외로 만들어 “이미 유연했던 적이 있다”는 근거가 생기게 한다.
- 긴급 건은 약 13% 포함한다.
- 데모 최소 규모는 주선사 5~10곳 × 각 30~50건 × 3개월, 총 200~400행이다.
- 패턴 성립 최소 기준은 3개월 20건 이상, 동일 노선 3건 이상이다.

## 탄소 산정 기준

### 기본 변수

- `d_R`: 적재 운행거리
- `g`: 접근 공차거리
- `t`: 톤급
- `r_now`: 현재 실측 복화율
- `β_R`: 역방향 물동량지수
- `w`: 현재 시간창
- `W`: 최대 개방 시간창, 48시간

### 산정식

```text
E = d_R × EF적재(t) + g × EF공차(t) + d_R × EF공차(t) × (1 - r_now)

ΔE_A = d_R × EF공차(t) × (β_R - r_now)

ΔE_B = ΔE_A × (1 - w / W),  W = 48h
```

- 방식 A는 잠재 추가 감축량이다.
- 방식 B는 현재 시간창을 고려한 조건 개방 실현량이다.
- 국내 경유 배출계수는 `2.609 kg CO₂/L`이며 TTW(연소) 기준이다.
- 거리당 계수는 `EF(kg CO₂/km) = 경유계수(kg/L) ÷ 연비(km/L)`로 계산한다.

톤급별 가정:

| 톤급 | 적재 연비 km/L | 공차 연비 km/L | EF 적재 kg/km | EF 공차 kg/km |
| --- | ---: | ---: | ---: | ---: |
| 5t | 5.5 | 7.0 | 0.474 | 0.373 |
| 11t | 4.0 | 5.0 | 0.652 | 0.522 |
| 25t | 3.2 | 4.0 | 0.815 | 0.652 |

### 12,000건 가상 데이터 적용 결과

- 기본 총배출량: 3,398.5 tCO₂
- 방식 A 감축: 739.4 tCO₂, 21.8%
- 방식 B 감축: 673.5 tCO₂, 19.8%
- 방식 B 건당 평균 감축: 56.1 kg
- 공차 감축거리: 1,290,097 km
- 연료 절감: 258,148 L
- 경유 1,503원/L 기준 비용 절감: 387,919,070원
- 화주 300곳 배분 평균: 1곳당 2.25 tCO₂

### 반드시 함께 표시할 한계

- 경유 배출계수와 연료가는 국내 공식값이지만 톤급별 연비는 업계 평균 추정이다.
- 결과는 `가상데이터 찐 최종.xlsx (v13)` 12,000건에 적용한 값이다.
- 현재 복화율 1.6%는 운송 이력에서 36시간 내 권역 연결로 측정한 값이며, 산업 공차율과 차이가 커 데이터 한계가 있다.
- 실서비스에서는 차량별 실연비, 실연료, 텔레매틱스 기반 복화율로 교체해야 한다.
- 현재 값은 TTW 기준이다. WtW가 필요하면 연료 상류 배출을 별도로 반영한다.
- 물리적 감축은 하나이며 운송인 비용 효과와 화주 Scope 3 배분을 이중 합산하지 않는다.

## 예외 처리 기준

- 조건을 바꾸지 않는 화주는 그대로 수용하고 이유를 학습한다.
- 신규 화주는 유사 사용자 데이터와 초기 선호를 사용하되 낮은 신뢰도를 표시한다.
- 긴급 물량은 자기 신고 대신 노선 평균 대비 리드타임 하위 20%로 판별한다.
- 긴급 건은 벤치마크·등급에서 분리 집계하되 별도 인사이트로 제공한다.
- 진짜로 조건을 바꿀 수 없는 화주는 통제 영역 밖으로 인정한다.
- 후보가 모두 별로인 경우 선택하지 않는 것도 정당한 의사결정으로 기록한다.
- 적합한 운송인이 없을 때는 결국 일반 순번으로 노출될 수 있어야 한다.
