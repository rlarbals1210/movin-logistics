# MOVE-AI Challenge 2026 | Team Mov!n

발주 조건을 완화했을 때 수락 가능 차주 수·운임·배차 시간의 변화를 비교하는 **조건 유연성 진단 기반 화물 운송 매칭 AI** 프로토타입입니다.

## 행사와 팀

- 해커톤: **MOVE-AI Challenge 2026**
- 주최: **국토교통부**
- 참여기업: **카카오모빌리티 · 코레일 · 현대글로비스**
- 팀명: **Mov!n**
- 구성: 5명

Mov!n은 프로젝트명이나 해커톤명이 아니라 이 대회에 참여한 팀명입니다.

## 문제 정의

화주는 배차 실패를 줄이기 위해 어떤 조건을 얼마나 완화해야 하는지 판단하기 어렵고, 차주는 운임·거리·시간창 등 여러 조건을 함께 고려합니다. 이 프로젝트는 조건을 바꿨을 때의 예상 수락 가능성과 비용 변화를 한 화면에서 비교하는 것을 목표로 했습니다.

## 김규민 담당

- 백엔드·AI 담당
- CPIM 보유 팀원의 물류 도메인 요구를 피처와 API 응답 기준으로 번역
- 공개 자료와 현업 인터뷰를 바탕으로 가상 콜 12,000건 설계
- 데이터 생성 규칙의 논리모순 검증
- 수락 예측·조건 완화 반사실 예측과 조건 스윕 시뮬레이션 구현
- 프론트엔드가 사용할 수 있도록 모델 결과를 API 단위로 연결

## 모델과 시뮬레이션

| 항목 | 결과 |
|---|---:|
| 수락 예측 ROC-AUC | 0.720 |
| 시간창 완화 반사실 예측 ROC-AUC | 0.747 |
| 조건 조합 스윕 | 30회 |
| 조건 4종 평균 수락률 변화 | +14.78%p |
| 배차 성공 변화 | +102건 |

위 수치는 **가상 데이터 기반 시뮬레이션 결과**입니다. 실제 화물정보망의 운영 성과나 현장 인과효과로 해석하지 않습니다.

## 저장소 구조

- `ai/`: 가상 데이터·모델·시뮬레이션
- `backend/`: 모델 및 서비스 API
- `frontend/`: 사용자 화면
- `docs/`, `design/`: 기획·설계 자료
- `.env.example`: 필요한 환경변수 예시

## 기술 스택

Python · scikit-learn · HistGradientBoosting · KMeans · statsmodels · Gemini API · TypeScript

## 한계와 다음 단계

- 실데이터가 아니라 공개 자료를 바탕으로 설계한 가상 데이터입니다.
- AUC와 시뮬레이션 결과는 동일한 생성 규칙 안에서 측정되어 실제 환경으로 일반화할 수 없습니다.
- 실제 적용 전에는 화주·차주 행동 로그로 외부 검증하고, 비용·지연시간·안전 지표를 함께 확인해야 합니다.
- 공개 데모는 현재 운영하지 않습니다. 저장소의 코드와 문서를 기준으로 확인해 주세요.
